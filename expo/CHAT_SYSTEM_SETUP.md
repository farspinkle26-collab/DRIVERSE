# Chat System Setup Guide\n\nThis guide explains how to set up and use the real-time messaging and chat system between users and drivers using Supabase.\n\n## Database Setup\n\n### 1. Run the SQL Setup\n\nFirst, you need to run the SQL commands in your Supabase SQL editor:\n\n1. Open your Supabase project dashboard\n2. Go to the SQL Editor\n3. Copy and paste the contents of `chat_system_tables.sql`\n4. Execute the SQL commands\n\nThis will create:\n- `tow_requests` table for storing towing requests\n- `chat_messages` table for storing chat messages\n- Indexes for better performance\n- Row Level Security (RLS) policies\n- Real-time subscriptions\n- Automatic system message triggers\n- Helper functions for marking messages as read\n\n### 2. Enable Realtime\n\nMake sure Realtime is enabled for the tables:\n1. Go to Database > Replication in your Supabase dashboard\n2. Enable replication for `chat_messages` and `tow_requests` tables\n\n## Features\n\n### Real-time Messaging\n- Messages are delivered instantly using Supabase Realtime\n- Support for text, location, system, and image messages\n- Read receipts and message status tracking\n- Automatic system messages when request status changes\n\n### Message Types\n- **Text**: Regular chat messages\n- **Location**: GPS coordinates with formatted display\n- **System**: Automated status updates\n- **Image**: Image sharing (future enhancement)\n- **Status Update**: Request status changes\n\n### Security\n- Row Level Security ensures users can only see their own messages\n- Proper authentication checks for all operations\n- Secure real-time subscriptions\n\n## Usage\n\n### 1. Creating a Tow Request with Chat\n\n```typescript\nimport { useChat } from '@/hooks/useChatStore';\n\nfunction RequestTowScreen() {\n  const { createTowRequest } = useChat();\n  \n  const handleCreateRequest = async () => {\n    const request = await createTowRequest(\n      pickupLocation,\n      dropoffLocation,\n      vehicleInfo,\n      breakdownInfo,\n      serviceType,\n      distanceKm,\n      priceIdr\n    );\n    \n    if (request) {\n      // Navigate to chat or payment\n      router.push(`/chat?requestId=${request.id}&receiverId=${driverId}`);\n    }\n  };\n}\n```\n\n### 2. Check if Realtime is enabled for the tables\n   - Verify RLS policies are correct\n   - Check browser console for subscription errors\n\n2. **Permission denied errors**\n   - Ensure user is authenticated\n   - Check RLS policies match your user structure\n   - Verify foreign key relationships\n\n3. **System messages not sending**\n   - Check if the trigger function is created\n   - Verify the system user ID in the trigger\n   - Check database logs for errors\n\n### Debug Mode\n\nEnable debug logging:\n\n```typescript\n// In your chat hook\nconsole.log('Setting up real-time subscriptions for user:', user.id);\n```\n\n## Next Steps\n\n1. **Image Sharing**: Implement image upload and sharing\n2. **Push Notifications**: Add push notifications for new messages\n3. **Message Encryption**: Add end-to-end encryption\n4. **Voice Messages**: Support for voice message recording\n5. **File Sharing**: Allow document and file sharing\n6. **Message Search**: Add search functionality\n7. **Chat History Export**: Allow users to export chat history\n\n## Security Considerations\n\n- All messages are protected by RLS\n- Users can only access their own conversations\n- System messages are sent by a dedicated system user\n- Real-time subscriptions are filtered by user ID\n- No sensitive data should be stored in message content\n\nThe chat system is now fully integrated with your towing app and provides real-time communication between customers and drivers throughout the entire service process.
